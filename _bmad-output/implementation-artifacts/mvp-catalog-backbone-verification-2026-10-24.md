## Lifecycle and integration contract

`openBundledUsdaCatalog(driverFactory, sha256): BundledUsdaCatalogSession?` takes a
fresh private synchronous driver. Android/Native drivers create the exported
`usdaCatalogSchema`; JDBC fixtures create it explicitly. The session implements
`ApprovedNutritionCatalog` and exposes `catalog` as that SQL-free domain port.
It owns its driver, closes idempotently even after a close failure, and refuses
lookups/search after closure. The domain resolver converts ordinary lookup
failure to `SOURCE_UNAVAILABLE`; cancellation propagates.

One Android ViewModel/SharedKit production session retains one catalog session.
Initialization belongs off the UI thread, followed by Main publication and
serialized access/disposal. A host already disposed at completion must close the
late result rather than publish it. Host implementation and native disposal
evidence are separate from these real JDBC lifecycle fixtures.
