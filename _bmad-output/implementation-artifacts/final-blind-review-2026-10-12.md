- **Retained selection can make a replacement evidence set impossible to edit.** Demonstrated from source. [PhotoAnalysisFeature.kt:63](REDACTED_WORKTREE/a704/SuperNutrition/mobile/feature/photo-analysis/src/commonMain/kotlin/com/supernutrition/feature/photoanalysis/PhotoAnalysisFeature.kt:63) clears the new selection only for the four events at lines 146–153. The existing valid `CandidateReview -> GridCellSelected -> Ready -> AnalysisStarted -> ReviewEvidenceAvailable` transition replaces the draft without any of those events (`PhotoAnalysisReducerTransitions.kt:85,101`). Select component A, then reanalyse into a draft containing B and no A. A remains in `mealReviewSelection`. Clicking B sends the copied set `{A,B}`, which [PhotoAnalysisFeature.kt:80](REDACTED_WORKTREE/a704/SuperNutrition/mobile/feature/photo-analysis/src/commonMain/kotlin/com/supernutrition/feature/photoanalysis/PhotoAnalysisFeature.kt:80) rejects because A is no longer evidence. A cannot be deselected because its tile is gone. The footer also enables Add from the nonempty stale set (`PhotoAnalysisMealReview.kt:156`), while confirmation filters it to no current IDs (`:183`) and the feature rejects the empty payload. Reconcile choices when evidence identity changes, and verify that B can be selected and confirmed after this sequence. This is an existing explicit reanalysis/API path, not a claim that ordinary consumer navigation currently exposes the diagnostic grid.

- **The retained-photo review removes its exit action on iOS.** Demonstrated from source. [PhotoAnalysisCameraScreen.kt:93](REDACTED_WORKTREE/a704/SuperNutrition/mobile/feature/photo-analysis-ui/src/commonMain/kotlin/com/supernutrition/feature/photoanalysis/PhotoAnalysisCameraScreen.kt:93) renders Close only when `!reviewing`. The reviewing branch offers Retake and Add, without rendering the presenter's Cancel action. Android supplies a BackHandler, but the production iOS host [SuperNutritionApp.swift:36](REDACTED_WORKTREE/a704/SuperNutrition/mobile/apps/iosApp/SuperNutritionApp.swift:36) has neither a navigation/back shell nor another exit control. With no selected foods, Add is disabled, leaving Retake as the only way out; it clears the old review and immediately opens native capture (`PhotoAnalysisViewController.kt:35`). Provide a nondestructive close/back route for review and check the no-selection case. Whether closing should preserve or cancel the draft must follow the existing host/session intent rather than silently choosing a new retention policy.

- **An unfamiliar food has no visible selection cue other than color.** Demonstrated from source. [PhotoAnalysisFoodPalette.kt:90](REDACTED_WORKTREE/a704/SuperNutrition/mobile/feature/photo-analysis-ui/src/commonMain/kotlin/com/supernutrition/feature/photoanalysis/PhotoAnalysisFoodPalette.kt:90) changes the unknown-food background to green, while its border and text remain unchanged. The only visible checkmark is inside `FoodStickerArtwork` (`:131`), which is never called when `foodStickerFor` returns null (`:112`). Select “Homemade banana bread”, an explicitly tested valid fallback label: only the background color changes. Selected/stateDescription semantics are present, but they do not provide the architecture's required visible non-color state cue for sighted users who cannot distinguish the colors. Give text fallbacks a checkmark or equivalent visible marker as well as their existing semantics.

- **Confidence, ambiguity, partial visibility, and mass evidence are available only to accessibility services in the consumer review.** Presentation question, with the omission demonstrated from source. [PhotoAnalysisFoodPalette.kt:115](REDACTED_WORKTREE/a704/SuperNutrition/mobile/feature/photo-analysis-ui/src/commonMain/kotlin/com/supernutrition/feature/photoanalysis/PhotoAnalysisFoodPalette.kt:115) visibly renders only the label; `reviewDescription()` puts the other supplied facts in contentDescription. `PhotoAnalysisReviewEvidenceTest.kt:36` tests only that contentDescription for low-confidence, ambiguous, partly visible foods. Consequently such a food looks like a clear high-confidence food to a sighted user, and an actual mass range would not be visually discoverable. Resolve whether the approved consumer scope needs a compact uncertainty/details affordance, and validate its visible behavior; this review does not assert an observed wrong-food confirmation.

- **Confirmation cannot be tied to the originating photo or request.** Contract risk, not a reproduced asynchronous UI failure. [PhotoAnalysisMealReviewConfirmation.kt:4](REDACTED_WORKTREE/a704/SuperNutrition/mobile/feature/photo-analysis-presenter/src/commonMain/kotlin/com/supernutrition/feature/photoanalysis/PhotoAnalysisMealReviewConfirmation.kt:4) contains evidence IDs but no photo/request token. `confirmMealReview` validates those strings against whichever draft is current. Native evidence IDs are reused for the same ordinal/label across photos (`SharedKitPhotoAnalysisSession.kt:223`), so a delayed host confirmation from an earlier photo could pass when the newer draft contains the same IDs. The current click callback is synchronous, which limits immediate exposure. Bind the handoff to an immutable review/photo identity before introducing asynchronous consumers, or document a strictly synchronous lifetime contract.

- **Swift receives a completion signal but cannot retrieve the confirmed draft.** Handoff/design question. [PhotoAnalysisNativeCallbacks.kt:7](REDACTED_WORKTREE/a704/SuperNutrition/mobile/feature/photo-analysis/src/iosMain/kotlin/com/supernutrition/feature/photoanalysis/PhotoAnalysisNativeCallbacks.kt:7) exposes a zero-argument completion callback; [PhotoAnalysisViewController.kt:58](REDACTED_WORKTREE/a704/SuperNutrition/mobile/feature/photo-analysis/src/iosMain/kotlin/com/supernutrition/feature/photoanalysis/PhotoAnalysisViewController.kt:58) discards the payload after saving it internally. `SharedKitPhotoAnalysisSession.feature` is internal and has no public confirmed-review accessor; no production reference reads `confirmedMealReview`. The Swift host can therefore show the new alert, but cannot inspect or pass on which components/note were confirmed. Confirm whether internal retention alone meets the requested “hands off an explicit session-local meal draft”; if an actual native handoff is required, expose a payload/read API without pretending this is catalog-grounded meal persistence.
