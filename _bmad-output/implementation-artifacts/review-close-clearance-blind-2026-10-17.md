## Introduced production defects

- `PhotoAnalysisMealReview.kt:90–93` caps the reserve in dp before the padding and action minimum are independently rounded to pixels. This can still leave less than the promised minimum touch viewport. At density `1.34375f` (215 dpi), a 134 px parent exposes `maxHeight = 99.720932.dp`; subtracting 48 dp produces `51.720932.dp`, which rounds to 70 px of top padding. The actual scroll viewport is therefore 64 px, while 48 dp rounds to 65 px. `PhotoAnalysisReviewActions.kt:73–76` gives the action at least 65 px, so it is clipped by one pixel; the focus helper also receives a nominal 65 px viewport although only 64 px is available. The pre-N-29 compact viewport reserved no top padding and did not have this shortage. Calculate the cap from integer `constraints.maxHeight` minus the rounded minimum touch pixels, then derive both the padding and relocation viewport from those same integers. Add a regression at non-unit density that compares visible bounds against the rounded 48 dp minimum. This is a statically demonstrated pixel-rounding defect; it has not been executed as a Compose test by this reviewer.
