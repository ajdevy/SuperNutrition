- (decision) Target users are in Tier 1 country markets; define English-first beta and country-configurable food data, units, privacy, and provider region.
- (decision) Both local and remote photo inference are MVP requirements behind one versioned engine contract.
- (decision) Models return candidates and uncertainty; numeric nutrition is calculated only from confirmed versioned nutrition records.
- (decision) Remote escalation is explicit and consented; local failure never silently uploads a photo.
- (decision) Confirmation of food identity and serving assumption is required before grounded nutrition is calculated.
- (decision) Tier 1 country users are the initial market segment; English-first beta remains country-configurable.
- (decision) Local and remote implementations are separate modules epics owners and pull requests; orchestration is a third integration boundary.
- (decision) Koin is selected for DI and Decompose is limited to lifecycle and real navigation while the analysis flow is one state machine.
- (decision) New deterministic code maintains 100 percent automated coverage and hardware behavior requires physical-device evidence.
- (assumption) The first internal beta has no account or persisted meal history.
- (assumption) Both platforms are required for MVP acceptance but local engines may arrive in separate platform stories.
- (assumption) The 300 to 500 plus meal benchmark and legacy latency targets are provisional until the device and country matrix is selected.
- (change) Reviewer gate resolved Tier 1 reference cohort route-platform matrix benchmark validity hybrid advantage UX posture consent cancellation semantics and owned decision gates.
- (event) PRD finalized after source reconciliation KMP review rubric review structural review and prose review
- (decision) Testing policy now has two thresholds: every covered production module and the aggregate must maintain at least 85 percent unit-test line and branch coverage, while changed deterministic code remains at 100 percent where measurable.
- (decision) Every positive PRD user journey is automated as UI acceptance: Kaspresso with Compose support on Android and equivalent XCUITest coverage on iOS, using deterministic test engines and data rather than asserting real-model accuracy.
- (decision) GitHub Actions runs the complete host-compatible automated verification matrix on every push to every branch and every pull request without path filters; required jobs fail closed and physical-device evidence remains separately gated.
- (decision by user) Supersede the split Kaspresso/XCUITest journey suite with layered cross-platform UI acceptance: Compose Multiplatform UI tests cover shared semantics, rendering, and state contracts; Maestro CLI 2.7.0 runs the same packaged-app positive journeys on Android and iOS; native instrumentation or XCTest remains only for platform bridge, system UI, accessibility, and physical-device gaps.
- (decision) NFR-17 now assigns every compiled production source to one coverage or executable-equivalent denominator, enforces 85% line and branch per JVM/Android module and deduplicated aggregate, and requires 100% for changed production lines and branch outcomes.
- (decision) NFR-20 completeness is defined by a closed UJ-1 through UJ-4 and SM-9 scenario catalog; each entry uses one Android/iOS journey definition plus linked privacy, network, and native-gap evidence.
- (decision) NFR-21 also covers enabled merge queues; platform completeness and non-visual transfer evidence are closed and platform-specific rather than inferred from one shared mock result.
- (event) PRD finalized after cross-platform UI-test and fail-closed CI strategy update.
- (decision by user) The repository is a monorepo with separate root product boundaries for the Kotlin Multiplatform mobile app, the public web landing site, and the backend serving the mobile app.
- (event) PRD and addendum finalized with the monorepo product-boundary, independent contract, six-job CI, coverage, and agent-ownership requirements.
