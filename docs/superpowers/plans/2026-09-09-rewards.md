# Rewards Feature Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a positive, simple Rewards tab whose cards are earned only from confirmed, catalog-grounded food entries and whose daily/weekly rules match the supplied `Карточки Награды.docx` brief.

**Architecture:** Keep the first vertical slice inside the existing bounded modules to avoid inventing a new production module and changing policy inventories. Add the reward contract/evaluator to `domain:nutrition` because it consumes confirmed catalog nutrition facts; add the stateful confirmed-entry ledger and presenter to the existing photo-analysis composition feature; add a shared Compose list to the existing photo-analysis UI module. Android and Apple hosts expose the same two-tab surface. The ledger has a storage port and an in-memory implementation for this slice; current photo/manual suggestion flows do not write to it because the repository's catalog is identity-only and has no grounded nutrient values until the real “confirm and add to day” flow is available.

**Tech Stack:** Kotlin Multiplatform, Kotlin coroutines `StateFlow`, Compose Multiplatform/Material 3, SwiftUI host tabs, Kotlin/JVM tests, existing Android quality entrypoints.
